## What changed

- A notification carries one button where exactly one action exists, beside the **Reply** field a message has (macOS): **Answer** on a question opens the window at it; **Allow once** on a command a Codex session asks to run answers it `Allow` through the notification's daemon without opening the window (a refusal is said as a further notification and the question stays in the app); **Go to Terminal** on a stop in an agent's own terminal brings that terminal forward through the window of the notification's workspace. A finish keeps no button: clicking it opens the app.
- One state is told once. `agentdocker_core::notification::Told` is the pure ledger (tag → state, unit-tested): the window keys its notices by `window.<agent>` and by what it says (the stop's reason and detail, or the finish), so the same stop reported again, or a repeated focus event, posts nothing; a changed ask (another reason, another command) is news and replaces the last; a stop the daemon already asks about as a question has the question's notification only.
- The "already in front of the person" rule is a predicate the poster asks of every surface (`agentdocker_host::notify::Surface`, `shown`), with the focused window (`viewing.json`) as the one surface today; a later menu-bar panel implements the trait and is listed in `surfaces`, with no further check inside a poster. The window asks the same predicate for its own notices.
- Wire contract: the notification JSON gains an optional `button`; native content stores it in `userInfo["agentdocker.button"]` under one category per button (`dev.agentdocker.message|question|command|terminal`).

## How to try it

With the app installed and the window not in front: a Codex command approval posts one notification with **Allow once** and **Reply**; a question with a form or choices posts one with **Answer** and **Reply**; a Claude Code session stopped at a permission prompt posts, after two seconds, one with **Go to Terminal**. Leave the prompt where it is: no second notification comes. Answer it at the terminal and let it stop again: it is told again.

## What it will not do

- Linux: `notify-send` carries neither the Reply field nor a button, since it cannot hand a choice back to a process that has exited. Windows posts no desktop notifications.
- A Claude Code permission prompt cannot be allowed from a notification: no hook answers it, so its one action is Go to Terminal.
- Go to Terminal for another workspace reaches a running window of that workspace; with none running, a notification says to open the app there.
