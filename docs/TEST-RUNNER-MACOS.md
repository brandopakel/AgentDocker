# macOS test-runner descriptor inheritance

The September 7 installer diagnostics reproduced `LEAK-FAIL` on filesystem-only tests under stock cargo-nextest 0.9.143 on Apple Silicon. No test spawned a subprocess. Two instrumented runs each failed on the third iteration, on different tests. Passing reruns alone do not resolve these failures.

Process and descriptor captures identified a sibling as the holder: test PID 89747 had descriptor 40 connected to the same pipe endpoint as test PID 89748's stdout (descriptor 1). PID 89747 retained that pipe after 89748 exited. It also inherited the corresponding reader. This proves cross-test descriptor inheritance in the runner's process creation path for this reproduction; it is not evidence that SQLite teardown merely took longer.

Rust's Darwin pipe implementation calls `pipe()` followed by separate close-on-exec updates. Concurrent creation/spawning can inherit descriptors within that interval. A diagnostic build of nextest 0.9.143 serialized its complete test-command pipe setup/spawn using a process-wide mutex on macOS. The original preserved test binary then passed 40 stress iterations with concurrent test execution. Stock nextest with serial test execution passed 20 iterations. An intentionally leaked `sleep` child still produced `LEAK-FAIL` with the original 500 ms limit and serial execution, and the diagnostic cleaned up that owned child.

The repository uses a macOS-only test group with one active test process as a temporary workaround. It keeps zero retries, `flaky-result = "fail"`, and `leak-timeout = { period = "500ms", result = "fail" }`. Linux scheduling is unchanged; each test's internal threads, clients and processes still run concurrently. This trades macOS suite duration for reliable process isolation. No patched nextest binary is installed globally or required by CI. Remove the workaround only after a released runner fix passes the original stress reproduction and intentional-leak control.

Raw logs, the preserved failing binary, instrumented runner patch, checksums and owned-process captures are in the private session handoff. The finding does not dispose of unrelated historical leak failures without matching evidence. Reference implementation: [nextest test-command spawning](https://github.com/nextest-rs/nextest/blob/cargo-nextest-0.9.143/nextest-runner/src/test_command/imp.rs), [Rust Unix pipe implementation](https://github.com/rust-lang/rust/blob/1.98.1/library/std/src/sys/pipe/unix.rs), and [nextest leak semantics](https://nexte.st/docs/features/leaky-tests/).
