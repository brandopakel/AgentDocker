# Storage and open-PR integration review

This candidate integrates the heads of #72, #74, #75, #78, #82, #83, #87,
#88, #90, #91, #92, #93, #94 and #95. There were no open GitHub issues at
inspection. Merge ancestry preserves the component commits and their evidence;
overlapping merges retain the newer capture recovery, desktop naming and audit
records. Source integration does not upgrade an installed running daemon.

## Findings checked without adopting the suggested change

The Windows desktop-module finding identifies existing platform work, rather
than a new Windows build regression. The daemon and CLI still use Unix signal,
process, PTY and socket modules; gating only `desktop` does not make those crates
Windows-compatible. The existing Windows workflow builds/tests core and host
foundations. Full daemon/CLI/GUI parity remains explicitly tracked in
[DELIVERY-PLAN.md](DELIVERY-PLAN.md); this candidate makes no Windows app claim.

The optional Claude activity lookup optimization is deferred. Coordination and
activity deliberately retain separate failure behavior and fresh identity
validation within the existing absolute phase budget. Changing the adapter's
return contract merely to reuse that lookup is unnecessary for these correctness
fixes. The lookup remains bounded; no reduced round-trip claim is made.

The older storage fallback finding is already fixed in the integrated input:
allocated directory blocks are counted with inode deduplication, with a no-`du`
regression. The earlier screenshot retry comments no longer exist in the current
capture implementation.

## Local cleanup scope

The first pass removed 35,038,208,000 allocated bytes of inactive Cargo output,
including cross-target, coverage, fuzz and temporary tool build caches. A second
pass removed approximately 1.28 GB of package-download and Go build caches.
Source, local changes, reports, handoff evidence, installed applications, provider
configuration and binaries used by running daemons were preserved. These are
allocated-file totals, not a promise of identical APFS free-space changes.

Personal application caches require a separate retention decision. Rust build
output is not shipped to end users. Final executable and archive measurements
belong to the package manifest; final CI and package acceptance must pass before
integration.
