Card AD-144 (statistics): each session's context use, from its provider's own counts.

## What changed

- **Core** — `usage::context::Context` (the latest request's `used_tokens`, the model's `window_tokens`, `model`, and its source: `runtime`, `format`, `record`, `at`) with `percent()` and `label()` (`Context 62 %`), and `window_tokens(model)`: a small table keyed by the model name a Claude Code transcript carries, with `[1m]` read as the one-million-token variant and nothing for a name it does not know. `usage::report::Report` gains an optional `context` map by agent id (absent from older daemons, empty while collection is off).
- **Host** — `usage::context(record, sample)`: a Claude Code assistant record gives the request's total input (uncached, cache read and cache creation together) against the table's window; a Codex `token_count` record gives `last_token_usage.input_tokens` against the `model_context_window` it states itself. A record that counts no input, a sidechain's, or one whose window is unknown states nothing. The reader's `Batch` carries each session's latest stated context.
- **Daemon** — a `usage_context` table (per runtime and session, counted against the tracking capacity, pruned with retention), written in the same transaction as the batch's samples and cursor and replaced only by a record no older than the kept one; the `usage` answer fills `context` for the agents in scope whose `session_id` label names a session a record speaks for, only while collection is on.
- **App** — the session row's hint and its Details show `Context 62 %` as text, and nothing where there is no figure.
- **Docs** — ARCHITECTURE (the request table, the response schema, a *Context used per session* bullet saying what is read and that it is an estimate), DESKTOP-UX and GUIDE.

## How to try it

With `[usage] enabled = true` in `agentd.toml`, run a Claude Code or Codex session registered with AgentDocker, let the collector catch up, then point at the session's name in the app's session list or open its Details; `agentdocker usage --json` shows the same under `context`.

## What it will not do

- It is an estimate from the provider's own counts: the size of the latest request as the provider reported it, against a window the record states (Codex) or a table knows (Claude Code). It does not predict the next request or when the provider will compact, and a figure over 100 % means the table, not the counts, is off.
- A model the table does not know shows nothing; so does a session with no record, a record that counts no input, and a sub-agent's sidechain record.
- Nothing is shown while collection is off, and the standalone `usage-scan` reports no context.
- No new event: the figure commits inside the batch's `usage_recorded` transaction.

## Tests

Core: the table and the rounding. Host: made-up fixtures of both record formats (known model, the `[1m]` variant, an unknown model, no input, a sidechain; a Codex rollout with and without a stated window). Daemon: the answer carries the latest stated record per session, drops it when collection is off, filters by agent, and has nothing for a session without a record. App: the row's spoken name and Details show the figure only when known.
